# 共テ数学60：アプリ単体到達性監査

- 監査日：2026-08-18
- 対象：main の監査対象コミット e2c108f
- 目的：外部教材を前提にせず、このアプリだけで共テ数学6割を目指せる土台になっているかを確認する
- 追加観点：ADHDを自己申告する利用者が、注意の切替・中断・再開で詰まりにくいか

## 判定

**FAIL：現時点で「このアプリだけで共テ数学6割に到達できる」とは言えない。**

アプリには、説明から確認問題へ進む導線、復習期限、全225概念への少なくとも一つの問題があります。一方で、共テ対象225概念の完全レッスン、本番形式の模試、得点換算、誤答原因に応じた再学習、中断位置の復帰が不足しています。したがって、現在の実装は「学習の入口と概念練習」としては有用ですが、「単独で6割到達を検証できる完成教材」ではありません。

この判定は診断や治療の評価ではありません。ADHD特性を想定した学習UXの不足を、継続しやすさと作業負荷の観点から確認したものです。

## 数値スナップショット

| 指標 | 現在値 | 読み方 |
| --- | ---: | --- |
| 全概念 | 320 | アプリ全体の概念数 |
| 共テ対象概念 | 225 | 数学I・A・II・B・Cの対象概念 |
| 完全レッスン | 100 / 225（44.4%） | 目標、考え方、例、ミス、確認、試験サインまで揃うレッスン |
| ガイド | 246 | 完全レッスンとは別の短い説明も含む |
| 問題 | 1,222 | 問題数。数だけでは本番対応の証拠にならない |
| 問題レイヤー | quick 446 / standard 451 / transfer 325 | 形式タグの集計 |
| 問題がない共テ概念 | 0 | 225概念すべてに少なくとも一問はある |
| 3層が揃わない概念 | 9 | quick・standard・transferのいずれかが欠ける |
| 現在のミニ模試 | 8問 | 画面上も本番得点には換算しないと明示 |

完全レッスンの内訳は、数学I 52/52、数学A 28/39、数学II 17/62、数学B 2/32、数学C 1/40です。特にB・CとIIの完全レッスン不足が大きく、ガイドだけで進む概念が125件あります。

## 監査方法

次の三つを組み合わせました。

1. データ集計：概念、レッスン、ガイド、問題、問題レイヤーの実数を集計。
2. 実装確認：app/page.tsx、app/problem-bank.ts、問題コンテンツ生成部分の導線を確認。
3. 独立レビュー：サブエージェント3件に、到達性、ADHD向け継続性、本番形式を分担して読み取り監査させた。

### 直接確認できた事実

- 共テ対象は225概念、完全レッスンは100件。
- 現在の模試は8問固定のスキル確認で、本番の点数には換算しないと表示される。
- Problem型と問題生成は単問中心で、大問、誘導、資料、配点、採点基準を表す本番用フィールドがない。
- 正答数は単純カウントで、時間制限や大問ごとの配点を使った本番採点はない。
- 誤答後の処理は、正答表示またはもう一度解くという一般的な導線で、誤答原因の記録と原因別の問題出し分けはない。
- ガイド閲覧や一度の試行が、概念ルートの完了・前提条件の通過に影響する。閲覧済みと自力で解けることが同じ扱いになり得る。
- 途中のレッスン画面を、離脱後に同じ位置から再開する状態保存が確認できない。

### 実用上の推論

- 完全レッスンが半分未満のため、外部教材なしで全範囲を説明から学ぶには穴が残る。
- 8問のスキル確認だけでは、長い資料の読解、誘導に沿った処理、時間配分、捨て問判断を練習できない。
- 誤答原因が残らないため、「計算ミスが多い」「条件の読み落としが多い」「方針が立たない」といった個別の詰まりに、次の一手を変えられない。
- ADHD特性を想定するなら、再開地点が曖昧なこと、画面内の情報量が多いこと、間違い後の選択肢が分岐することは継続の負荷になり得る。

### まだ証明できていないこと

- 実際の学習者が、外部教材なしで何週間・何時間で6割に達するか。
- 本番と同じ仕様の独立模試で、複数回安定して6割を取れるか。
- 個々の問題の難度・正答・解説が、全範囲で十分な品質か。
- ADHDの診断の有無に関係なく、どのUIがどの利用者に最適か。

## 強み

- 「次にやる概念」を選びやすく、最初の行動が比較的明確。
- レッスンに考え方、例、よくあるミス、確認問題が含まれる。
- 復習期限の概念があり、1・3・7・21日系の間隔を使う設計がある。
- 共テ対象225概念に問題自体は存在する。
- 問題やレッスンを増やせるデータ構造がすでにある。

## 致命的な不足

### P0-1：225概念を自力で学べる完全レッスンがない

完全レッスンは100/225です。残り125概念はガイドまたは問題中心で、外部教材を使わないという条件を満たす説明の連続性がありません。

### P0-2：本番形式と到達判定がない

現在の8問模試は、弱点を見つける入口です。本番形式の大問、誘導、資料、時間制限、配点、採点、復習レポートがないため、6割という数値に結び付けられません。

### P0-3：誤答原因からの再ルートがない

データ側には誤答タイプや翌日再テストに関する設計メモがありますが、現在のUIで原因を選び、保存し、原因に合う別問題を出す流れは未実装です。

### P1-1：閲覧・着手と習得が混ざる

ガイドを読んだ、一度試した、正答できた、転用問題を解けた、が同じ「ルートを進める」判定に近くなっています。これでは進捗表示が実力を過大評価する可能性があります。

### P1-2：中断からの復帰が弱い

レッスン内の位置、誤答後の次の一手、今日のセッション状態を保存していないため、短時間で中断しやすい利用者が同じ場所へ戻れる保証がありません。

## 最終結論

現状の正確な表現は、**「共テ数学の概念練習を始められるアプリ」**です。**「これ一つで共テ数学6割に到達できる教材」**と表示するには、次のアップデートと実測ゲートが必要です。

1. 共テ225概念すべてに完全レッスンを用意する。
2. 本番仕様を確認したオリジナルのフル形式模試を実装する。
3. 誤答原因、再開位置、習得判定を保存する。
4. 外部教材なしの条件で、異なる模試を複数回使った到達判定を行う。
