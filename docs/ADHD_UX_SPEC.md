# ADHD特性を想定した学習UX仕様

この文書は診断名に対する治療や効果を定めるものではありません。注意の切替、中断、作業記憶、開始の重さに困りやすい利用者を含め、学習の操作負荷を下げるためのプロダクト仕様です。

## UXの不変条件

### 1. 開いた直後の主行動は一つ

ホームで最初に目立つボタンは、「続きから」「今日の一問」など一つだけにします。計画、科目、難度、復習方式を最初から選ばせません。

### 2. 一画面一目的

一つの画面で、説明を読む、例を見る、答える、復習を決める、を同時に要求しません。現在の目的と次のボタンを上部に固定します。

### 3. 中断しても同じ場所へ戻れる

次を端末内に保存します。

- レッスンIDと画面位置
- 問題IDと回答途中の状態
- 誤答タイプ
- 次の再テスト日時
- 今日のセッションの残り

保存は自動で行い、離脱時に確認ダイアログを出しません。

### 4. 間違いの後に迷わせない

不正解後は、原因を一つ選ぶ、原因に合う短い説明を見る、別問題を一問解く、の一本道にします。正答表示だけで「習得済み」にはしません。

### 5. 短い時間でも完了になる

3分、10分、20分のセッションを用意します。3分を選んだ利用者に、長い計画や連続日数を要求しません。

### 6. 失敗を罰にしない

連続日数、遅れ、未達成を責める文言を使いません。再開時は「前回の続き」または「今日の一問」から始められるようにします。

## 1概念の標準フロー

1. 今日の目的を一文で表示。
2. 最小の考え方を一つ説明。
3. 例を一つ見る。
4. 確認問題を一問解く。
5. 不正解なら原因を一タップで選ぶ。
6. 原因別の短い復習を一つ行う。
7. 正答または「次回に続ける」を表示。

一つの概念に内容を詰め込みすぎず、詳細説明、標準問題、転用問題は別の再開可能なステップに分けます。

## 保存状態

| 状態 | 意味 | 次の主行動 |
| --- | --- | --- |
| 未開始 | まだ説明を開いていない | 説明を始める |
| 説明中 | レッスン途中 | 続きから読む |
| 確認待ち | 説明を読み終えた | 一問だけ解く |
| 誤答復習 | 原因を選んだ | 原因別の一問を解く |
| 習得確認待ち | 正答したが再確認が必要 | 翌日の再テスト |
| 完了 | 確認・標準・転用を通過 | 次の概念へ |

## 実装状況と残る確認

- レッスンは `overview` と `worked` に分かれ、現在の概念・問題・画面位置を保存して再開する。
- 不正解後は原因を一つ選び、原因別の別問題を予約してから再挑戦する。原因履歴も保存する。
- ガイド閲覧だけでは習得にならず、quick・standard・transfer・遅延再テストの正答証拠を別々に記録する。
- 3・10・20分の集中目安、画面を離れた時間の記録、前回の概念からの再開を実装している。
- 画面上の情報量と実機でのキーボード・読み上げ・狭い画面の操作性は、独立監査で継続確認する。

## 受け入れテスト

### 再開

1. レッスンの例題前でブラウザを閉じる。
2. 翌日に開く。
3. 画面の主ボタンが同じ概念の続きになっている。
4. 例題前から再開できる。

### 誤答

1. 確認問題を不正解にする。
2. 「条件の読み落とし」を一タップで選ぶ。
3. 読み落とし用の短い復習が出る。
4. 別表現の一問を解く。
5. 翌日の再テストに同じ概念が予定される。

### 3分セッション

1. 3分セッションを選ぶ。
2. 説明一つと確認一問を終える。
3. 時間が来ても未完了の罰表示が出ない。
4. 次回は同じ概念の続きから始まる。

### 進捗の正確さ

ガイドを読んだだけでは習得済みにならず、確認・標準・転用の状態が別々に表示される。
